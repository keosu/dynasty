# 山河纪：应用架构

## 产品结构

产品采用地图应用工作区：54px 顶部导航、44px 工具栏、弹性地图区、固定底部朝代时间轴。时间轴每轨 24px，高度按轨道数计算（四轨桌面 196px、手机 184px）。页面根节点锁定视口，地图和世系页不发生整页滚动；信息在可关闭、可调宽的侧栏内展开。手机默认收起探索栏。

列表主要文字为 14px、辅助信息为 12px，人物卡片标题 17px。`app.css` 末尾的阅读尺寸规则统一桌面与手机字号。世系默认一个 SVG 单位对应一个屏幕像素，节点 192×84；标题／姓名／纪年字号分别为 16／13／12px。按画布宽度安排列数，长图通过拖动阅读；“查看全图”显式缩小，重置恢复 100%，不为容纳更多人物自动缩小文字。

三种主题通过 `src/themes.css` 的统一语义色彩变量控制：青瓷亮色、静夜暗色、琉璃夜色。`src/theme.ts` 管理稳定 ID 与 `shanhe-theme` 存储偏好；`src/main.tsx` 在挂载前应用主题及浏览器栏颜色；`ThemePicker` 提供带预览的原生单选项，支持方向键、Escape、外部点击关闭。所有页面共用一个应用外框，历史政权配色仍由数据管理。

琉璃主题的颜色表达栏目、事件类别和选中状态，背景与同类卡片保持统一。事件由 `data-category` 映射到 `--category-color`，文字、图标、标签与地图热点相互对应；混合类别聚合点采用中性色。人物、时间轴不按 ID 或序号分配装饰色。

## 信息流

1. 选择朝代决定地图专题；只从与所选时间范围相交的参考图中选择最近者，无匹配时显示无图层。用户可从“疆域依据”手动参考其他年代，改变时间范围后取消手动指定。
2. 底部时间轴的左右拖柄决定起止年；同时筛选所有已收录政权的在位人物与事件，支持跨朝代区间。
3. 左栏在热点与君主列表间切换，支持类别和关键词筛选。选中事件会定位地图并打开右侧档案。
4. 图层支持历史疆域、河流湖泊、事件热点及经纬网。地图可滚轮缩放、双击放大、拖动和键盘移动。
   并立时期快捷入口跳到明确参考年并显示当年人物。场景将同张底图的多个政权作为整体选择，逐政权着色、标注和开关；`ConflictLegend` 提供可收起图例、都城、在位者及语音。
5. 世系页提供在位顺序／父子关系两个独立视图。复位逐段成节点，父子关系必须有明确原文依据。
6. 资料详情采用可展开章节，长篇内容按人物 ID 加载。浏览器语音读取文字内容。

## 分层

- `src/App.tsx`：Hash 路由、共享朝代与时间范围、全局检索，挂载全局主题选择器。
- 样式按 `src/styles.css` → `src/app.css` → `src/themes.css` 加载，分别负责基础阅读组件、紧凑布局及响应式、语义配色与主题外观。
- `src/pages/AtlasPage.tsx`：工作区、面板、筛选和地图联动。
- `src/pages/GenealogyPage.tsx`：按在位区间生成节点，区分年代排序和血缘证据，提供平移缩放和档案面板。
- `src/pages/EncyclopediaPages.tsx`：列表、完整详情与资料说明。
- `src/components/`：地图、双端时间轴、正文按需加载、语音与公共展示组件。
- `src/domain/`：类型、时间与搜索查询、球面多边形方向规范化、数据校验测试。
- `src/data/`：校订人物、事件、朝代基础资料，以及自动生成的索引和采集清单。数据不引用 React。
- `scripts/`：独立离线采集器，处理来源表、合并单元格、别名、复位、文章摘录和边界提取。
- `public/data/`：自然地理、带来源和年份的历史边界快照、独立人物正文、第三方许可证。

使用 React + TypeScript + Vite + D3 Geo。纯静态部署，无数据库和地图 API 密钥依赖。应用、第三方运行库和历史索引分块构建；人物正文通过本地 JSON 按需获取。

## 数据契约

- Dynasty：专题名称、历史起止年、都城、摘要、参考来源。新增的源表专题按名单跨度提供目录；无可靠边界时不生成疆域。
- Emperor：稳定 ID、朝代 ID、姓名／称号、多个在位区间、概要、校订评价、来源、父亲原文名称、正文 ID。
- HistoricalEvent：时段、地点坐标、事件类别、关联人物、摘要和正文。
- 历史参考图：朝代 ID、参考年、时段、单年／时期口径、教材衍生／未校订旧图类型、出处与页码、电子本存档、配准报告、覆盖说明、GeoJSON 要素。`src/domain/boundaries.ts` 负责来源合并与时间查询；新资料失败时也不得恢复已淘汰旧图。
- 并立场景：共享年份与来源，多个政权各自包含关联朝代ID、颜色、名称位置、都城坐标、简介和多边形。转换成带 `dynastyIds` 与 `polities` 的参考图；任一参与政权可匹配同一场景。时间轴按区间安排多条分段，不再将并立政权挤在同一行。
- 导入清单：来源、获取时间、成功数、分组统计、异常记录。

年份用历史纪年整数，公元前为负数，无0年。交接年包含两个区间端点，因此可以同时出现前后两位君主。源表可能包含前身、追尊、摄政、自立者或复辟，资料范围必须明确；原有校订区间优先，原文在位文字保留供核对。

## 后续维护

采集器使用缓存、限速与退避；生成资料与校订资料分开，不能覆盖人工校订。西汉、唐、清的教材底本、配准与尚未完成的疆域范围见 `BOUNDARY_SOURCES.md`；原有采集约定见 `DATA_IMPORT.md` 和 `DATA_GUIDE.md`。

进一步扩展应优先开展史料审订、来源版本锁定与边界校订；扩充现有并立场景的年份和政权覆盖，再增加古地名／古河道及完整的控制层级。未来可用相同数据契约接入资料审核后台。当前覆盖、缺口和接续步骤见 [HANDOFF.md](HANDOFF.md)。

## 验证

TypeScript 检查与生产构建；单元测试覆盖公元前年份、交接年、复位、名录和正文完整性、同名政权与人物别名、来源许可、球面多边形；浏览器验证主题持久化、双端拖柄、面板、地图交互、世系、详情按需加载、语音控制和移动端固定工作区。
